# Sandcastle bridge — repair in `tide setup`, detect in `tide doctor`

The runtime symlink at `<repoRoot>/.sandcastle` → **config directory** (`.tide/`) — the **sandcastle bridge** (CONTEXT.md) — gets a first-class lifecycle owner: `tide setup` repairs it (confirm-gated), `tide doctor` detects it as its check #1, and `tide run` no longer self-heals beyond creating a missing symlink. The bridge has six on-disk shapes; only "missing" and "symlink → `.tide/`" are intact, and any of the other four (symlink → wrong target, real directory empty, real directory with content, regular file) silently turn into a worktree-collision crash at the next `tide run`'s PR-submission step. Setup describes what is on disk, asks for explicit consent, and only then unlinks/rmdir/rm-rf and recreates the symlink — declined or cancelled (including non-TTY) is exit-non-zero with the bridge untouched.

## Considered

- **Status quo: silent bail in `ensureSandcastleSymlink` when `.sandcastle` is a non-symlink.** Rejected: every subsequent `tide run` then breaks at the PR-submission step's second `createSandbox` with a misleading "branch already checked out" error from sandcastle's `WorktreeManager`. The user's mental model says "fresh run, fresh state" but the bridge state survives across runs. Naming the broken state out loud (doctor) and offering a one-command fix (setup) closes the gap.
- **Self-heal in `tide run` instead of (or in addition to) `tide setup`.** Rejected: `tide run` is the long-running, side-effecty command — adding interactive `confirm()` prompts to its hot path conflicts with the queue-runner's "ask only at the start" UX, and a non-confirm-gated destructive repair is the wrong default for a command that can run for an hour. Setup is already the host's "make tide-shaped state real" entrypoint; the bridge belongs there.
- **Auto-repair on detection without confirmation.** Rejected: cases 5 (real directory with content) and 6 (regular file) can clobber user-authored state. A blanket auto-rm-rf at any non-symlink shape is too sharp; the savings vs. one `confirm()` are minimal.
- **Grade the destructiveness per case (auto-fix empty dir, error on dir-with-content).** Rejected: the matrix is harder to explain than a uniform "broken bridge → describe + confirm + repair." One control flow, one mental model. The describe-step lists what gets deleted, so the user has the same information either way.
- **Auto-migrate `.sandcastle/*` content into `.tide/*` before re-symlinking.** Rejected: merging two parallel filesystem trees with possible collisions (worktrees with the same name in both, log files, patches from `syncOut`) is the kind of code that's hard to test against real-world drift and easy to get subtly wrong. A loud error on the rare path is fine — the common case (empty subdirs from a mid-run break) is covered by the confirm-and-rmdir path.
- **`tide doctor` mirrors `tide setup`'s repair (dual repair entrypoints).** Rejected: every existing doctor check is read-only — gh auth, docker daemon, Linear API, etc. — and the user's mental model says "doctor tells me what's wrong, setup fixes it." Mixing in interactive repair muddies that and makes doctor unsafe to run from CI / pre-push hooks. Setup is the single repair surface; doctor's hint points at it.
- **Auto-accept on non-TTY (CI-friendly default).** Rejected: setup is a once-per-repo provisioning command — almost no real-world CI need — and a misconfigured CI job that silently nukes a `.sandcastle/` real directory is a worse failure mode than a CI job that reports "broken bridge, re-run from a terminal." Adopted instead: clack's `confirm()` + `isCancel()` returns cancel on non-TTY, which the caller treats as decline. Adding a `--yes` flag later is cheap if someone files an issue.
- **Bridge check anywhere other than #1 in doctor's order.** Rejected: the bridge has zero preconditions (no env, no config, no Linear, no GitHub) and a broken bridge invalidates the path assumptions every later check makes about `.sandcastle/`. Surfacing it first means the user fixes the foundational state before debugging downstream symptoms.
- **Keep `tide setup` and `tide doctor` on raw `stdout`/`stderr` writers.** Rejected: a confirm-gated repair flow on raw stdio is hand-rolled prompt parsing and TTY detection. Migrating both commands to `@clack/prompts` (already used by `tide run`) gives `confirm`/`isCancel`/`log.{success,error,warn}`/`spinner` for free, with a uniform UI across all tide commands. The migration ships as its own slice ahead of the bridge work so the bridge code is clack-native from the start.

## Consequences

`tide setup`'s contract widens from "Linear team resources" to "host-side filesystem + Linear team resources." Repair runs as the very first step, before env/config load, so a fresh-clone setup that fails on a missing `LINEAR_API_KEY` still leaves a healthy bridge. The decline / cancel path exits non-zero with the bridge untouched and the Linear half not attempted — this is intentional: a user who declines a destructive repair has not asked for any other work to happen.

`tide doctor` gains "sandcastle bridge" as check #1, ahead of "gh auth." The check inspects `<repoRoot>/.sandcastle` via `lstat`, classifies it into the six shapes, and returns ok / FAIL. The FAIL hint names the on-disk shape and points at `tide setup`. Doctor remains read-only — running doctor on a broken bridge does not modify the filesystem.

The work ships as three slices, each independently reviewable:

1. Migrate `tide setup` and `tide doctor` to `@clack/prompts`, no behavior change. Replaces the `SetupOptions.stdout/stderr` and `DoctorOptions.stdout/stderr` test seams with stubs of the clack surface (or behavioral assertions on return codes + side effects); the existing exact-string output tests are rewritten.
2. Bridge detect + confirm-then-repair in `tide setup`, clack-native. Inspect first, describe what's on disk, prompt to repair, repair on confirm, exit non-zero on decline.
3. Bridge check #1 in `tide doctor`. Detect-only; emit FAIL with a hint to run `tide setup`.

`ensureSandcastleSymlink` in `src/cli/run.ts` is preserved but loses its repair-on-non-symlink ambitions: it stays a "create-if-missing" safety net so `tide run` from a healthy clone still works without a pre-step. The full classification + repair lives in setup. A future change that drops the bridge entirely (when sandcastle exposes a config-directory override — see CONTEXT.md Flagged ambiguities) deprecates this ADR alongside `ensureSandcastleSymlink`, the patch in `patches/`, and the relevant CONTEXT.md entry.
